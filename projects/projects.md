## Project Standards

### Naming Convention
Projects are numbered sequentially with descriptive names:
- Format: `[NN] - [Project Name]`
- Example: `01 - CCAGA Website Design`

### Folder Structure
Each project follows the standardized structure:
```
[NN] - [Project Name]/
├── artifacts/
│   ├── Analysis/
│   ├── Requirements/
│   ├── Sample Data/
│   └── UI Mockups/
├── tasks/
├── main.md
├── project-plan.md
└── README.md
```

### Status Definitions
- **Planning**: Requirements gathering and initial planning phase
- **Design**: Architecture and design development phase  
- **Development**: Active development and implementation phase
- **Testing**: Quality assurance and testing phase
- **Launch**: Deployment and go-live activities
- **Completed**: Project successfully delivered and closed
- **On Hold**: Temporarily suspended or paused

### Integration Points
Projects integrate with organizational model through:
- Requirements processing using EDPS methodology
- Domain modeling and concept alignment
- Process integration and standardization
- Change management and tracking

## Project Lifecycle

### Phase Gates
1. **Initiation**: Project charter and team assignment
2. **Planning**: Requirements gathering and analysis
3. **Design**: Architecture and design specification
4. **Implementation**: Development and testing
5. **Closure**: Launch, handover, and documentation

### Required Deliverables
Each project must produce:
- Requirements specification (artifacts/Requirements/)
- Technical analysis (artifacts/Analysis/)  
- Task breakdown and tracking (tasks/)
- Project plan with PERT analysis (project-plan.md)
